# Tabs Component

## Problem

Build a reusable component that shows one content panel at a time. Users can switch panels by choosing a tab, each instance can start on a requested tab, and multiple instances must keep their selections independent.

## Conceptual model

A tab group needs one piece of changing state: the active tab value. Each item pairs a unique `value` with a visible `label` and a `panel`. The component owns its own active value, so two instances do not share state.

## API

```jsx
<Tabs
  items={[
    { value: "html", label: "HTML", panel: <p>Markup content</p> },
    { value: "css", label: "CSS", panel: <p>Style content</p> },
  ]}
  defaultValue="html"
  ariaLabel="Web foundations"
/>
```

- `items`: ordered tab definitions with unique values.
- `defaultValue`: optional initial selection. If it is absent or invalid, the first item is selected.
- `ariaLabel`: accessible name that distinguishes tab groups on the page.

## Implementation

`src/components/Tabs.jsx` keeps the selected value in local React state. It pairs every tab and panel with IDs generated by `useId`, exposes the ARIA tab roles and selected state, and hides inactive panels. The component uses roving `tabIndex` so only the selected tab is in the normal Tab order.

Arrow keys move between tabs and activate the next item. Home and End move focus and selection to the first and last item. A zero-item list renders nothing.

## Walkthrough

1. The component checks whether `defaultValue` matches an item.
2. It initializes state from that value or falls back to the first item.
3. Each tab button compares its value with the active value.
4. Clicking a tab updates only that instance's state.
5. The matching panel becomes visible; all other panels receive the `hidden` attribute.
6. Keyboard navigation selects and focuses the adjacent, first, or last tab.

## Playground demonstration

The Tabs project shows two independent, realistic groups: a Web foundations reference panel and a team workflow view. The first opens on HTML; the second opens on Build. Changing one demonstrates that the other group keeps its own selection.

## Edge cases

- No items: return no tab controls or panels.
- Missing `defaultValue`: select the first item.
- Unknown `defaultValue`: fall back to the first item.
- One item: render a single selected tab and its panel; keyboard navigation wraps to itself.
- Multiple instances: unique IDs and local state keep each group independent.
- Duplicate item values are invalid input because values identify tabs and panels.

## Tests

Run `npm test` in `todo-list/`. `src/components/Tabs.test.jsx` covers item rendering, initial selection, invalid defaults, click-to-panel switching, instance independence, keyboard navigation, and empty input. `src/App.test.jsx` verifies the sidebar opens the Tabs project.

## Complexity

For `n` tabs, rendering and lookup are O(n) time and O(n) space for the tab and panel elements. Selecting a tab is O(1) state work; React re-renders the component's O(n) children.
